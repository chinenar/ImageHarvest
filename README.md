# ImageHarvest 1.6.39

## 1.6.39 — แสดงคำแปลทับบนเว็บ

- ใน HarvestTS เปิดเครื่องมือแปล เลือก Google Translate หรือ AI และภาษาต้นฉบับ/ปลายทาง แล้วกด Start ระบบใช้ OCR รุ่นเสริมที่เร่ง GPU เมื่อ runtime พร้อม จับพื้นที่ข้อความ แปล และแสดงคำแปลบนภาพต้นทางโดยอัตโนมัติ
- กรอบตามภาพเมื่อเลื่อนหน้า ปรับขนาด หรือใช้ object-fit; ขนาดตัวอักษรลดให้พอดีกับพื้นที่ ปรับ Scale ในตั้งค่าได้ มีปุ่ม “ดูต้นฉบับ / ดูคำแปล” มุมซ้ายล่าง และชี้ข้อความเพื่อดูต้นฉบับพร้อมคำแปล
- ลายน้ำที่ยืนยันแล้ว กรอบไม่ชัดที่ถูกกันไว้ และคำแปลไม่สำเร็จ/เก่าไม่ถูกวาดทับ การจับภาพจาก HarvestTS ซ่อนชั้นคำแปลก่อน เพื่อไม่ OCR คำแปลซ้ำ
- OCR Lab: ใช้ “ผล Harvest ล่าสุด” หรือ “แคปแท็บ HarvestTS” ตรวจ/แปล แล้วกด “วางคำแปลบนเว็บต้นทาง” ได้ ภาพที่นำเข้าจากไฟล์ทั่วไปไม่มีตำแหน่งเว็บต้นทาง
- ภาพแคปยึดตำแหน่งเลื่อนและขนาด viewport ที่จับไว้ ถ้าขนาดหน้าเปลี่ยน ระบบขอให้จับใหม่; ภาพต้นทางบนเว็บยึดตำแหน่งของภาพและปรับตามขนาดได้
- ข้อความบนฉากหรือขอบที่ยังไม่แน่ใจใช้พื้นสี่เหลี่ยมทับเฉพาะข้อความ รุ่นนี้ยังไม่เกลี่ยคืนรายละเอียดฉากแบบ inpainting; มีการเก็บภาพ/ข้อความเดิมและสลับกลับได้
- ทดสอบ `npm run test:overlay`; ตัวอย่างคำแปลจริงและภาพผลลัพธ์: `test-results/translation-overlay/live-google-result.json`, `translated-manga.png`, `translated-manga.html`

## 1.6.38 — GPU OCR และอ่านเป็นชุด

- ใช้ Paddle GPU และ Manga OCR บน CUDA เมื่อ runtime ผ่านการทดสอบในเครื่อง อ่านไม่เกินสอง crop ต่อชุดและสี่บรรทัด Paddle ต่อ batch เก็บลำดับผลและตำแหน่งของแต่ละภาพ/variant
- แยก Paddle detector จาก recognizer ใช้ detector ร่วมกัน ลดการโหลดโมเดลซ้ำ และ batch เฉพาะขั้นอ่านบรรทัด ยังสแกนภาพเต็ม/ส่วนย่อยและภาพเดิม/CLAHE รวมถึงตรวจภาพปรับสีตามเงื่อนไขเดิม
- บน RTX 4070 Super: หน้าอังกฤษ 8.6 วินาทีรอบแรก / 4.2 วินาทีเมื่อโมเดลพร้อม, ญี่ปุ่น 14.1 / 9.1 วินาที, ไทยสังเคราะห์ 1.1 / 0.7 วินาที เวลานี้ไม่รวมการเริ่ม worker ที่ benchmark เตรียมไว้ก่อนหน้า และไม่ใช่ผลแคช ข้อความอ้างอิงครบ 8/8, 11/11, 3/3; คำผิดญี่ปุ่นเดิม 1 ตัว, SFX และกรอบบางจุดยังต้องตรวจ
- เครื่องไม่มี GPU runtime ใช้ CPU เดิมได้; หาก CUDA แจ้งหน่วยความจำไม่พอจะอ่านงานเดิมซ้ำบน CPU หนึ่งครั้ง ประวัติ OCR แสดง GPU/CPU ตามอุปกรณ์ที่ใช้จริง
- ติดตั้ง GPU runtime แยกด้วย `scripts/setup-ocr-gpu.ps1` หลังติดตั้ง base runtime ใช้แพ็กเกจที่ตรึงรุ่นและทดสอบ inference ก่อนเปิดใช้งาน; ใช้ `-ValidateOnly` เพื่อตรวจของที่ติดตั้งแล้ว ตั้ง `IMAGEHARVEST_OCR_DEVICE=cpu` เพื่อบังคับ CPU
- หลักฐานเวลาและคุณภาพ: `test-results/ocr-speed/gpu.json` และ `gpu-report.md` ยังไม่ยืนยันความแม่นยำ 99% ทั้งภาพหรือมังงะทุกเรื่อง

## 1.6.37 — OCR บนคอมเร็วขึ้นและแยกลายน้ำ

- เร่ง Paddle CPU ด้วย oneDNN บน runtime 3.2.2 ที่แยกติดตั้งจาก runtime เดิม และจำกัดเธรดให้เหมาะกับงาน OCR; ใช้โมเดล PP-OCRv5 เดิม โดยยังสแกนภาพเต็ม/ส่วนย่อยและภาพเดิม/CLAHE
- ตรวจยืนยันข้อเสนอญี่ปุ่นที่ไม่ชัดก่อน Manga OCR เพื่อไม่อ่านภาพที่ถูกปฏิเสธซ้ำหลายรอบ
- OCR Lab จำผลเมื่อภาพ ภาษา กรอบ ขนาด และการตั้งค่าตรงกัน ภายในหน้าต่างเดียวกัน ปิด “ใช้ผลเดิมเมื่อภาพ/การตั้งค่าตรงกัน” เพื่อบังคับอ่านใหม่ ผลแคชแยกจากการแก้ข้อความ/แปลและจำกัดหน่วยความจำ
- แยก RITHAR SCANS ที่ยืนยันแล้วออกจากการแปลอัตโนมัติ เก็บคำอ่านและกรอบเดิมไว้ตรวจ; ไม่ใช้คำว่า scans สี หรือชิดขอบเพียงอย่างเดียวตัดข้อความ
- ประเภทกรอบเพิ่ม “ลายน้ำ / เครดิต” และ “ภาพที่ไม่ใช่ข้อความ”; เปลี่ยนกลับเป็นข้อความทั่วไปแล้วบันทึกเพื่อคืนกรอบที่แยกผิด
- กรอบที่มีคะแนนต่ำกว่า 75 และยังรอตรวจจะไม่ส่งแปลโดยอัตโนมัติ ตรวจแล้วหรือเปิด “แปลกรอบความมั่นใจต่ำด้วย” ได้ กรอบญี่ปุ่นที่ไม่มีคะแนนไม่ถูกตัดเพียงเพราะไม่มีคะแนน
- เวลาจากหน้าทดสอบเดิม: อังกฤษ 260 → 75–123 วินาที, ญี่ปุ่น 198 → 91–100 วินาที, ไทยสังเคราะห์ 42 → 10–19 วินาที ข้อความและกรอบตรงกับผลเดิมทุกจุด การวัดเวลาขึ้นกับโหลดเครื่องและการโหลดโมเดล; ดู test-results/ocr-speed/report.md
- ติดตั้ง runtime เพิ่มเติมด้วย scripts/setup-ocr-runtime.ps1; runtime/model cache อยู่ในเครื่องแยกจากตัวติดตั้งแอป

## 1.6.36 — เชื่อม OCR กับ Google Translate และ AI

- OCR Lab: เลือก Google Translate หรือ AI ในเครื่อง, ภาษาต้นฉบับ/ปลายทาง, แปลทั้งภาพหรือเฉพาะกรอบ และกรองเฉพาะกรอบที่ตรวจแล้วได้
- ดูข้อความต้นฉบับกับคำแปลในกรอบเดียวกัน พร้อมประวัติผู้ให้บริการ/โมเดล ภาพต้นฉบับ และตำแหน่งเดิม บันทึก/เปิดกลับผ่านโปรเจกต์ OCR review
- AI ใช้ API ในเครื่องที่ 127.0.0.1:1234 และรับบริบทที่กรอก เช่น เรื่องย่อ ชื่อตัวละคร ความสัมพันธ์ เลือกโมเดลที่มีอยู่ในเครื่องได้ รอบนี้ส่งข้อความและบริบท; ยังไม่ได้ส่งภาพไปโมเดล
- HarvestTS หลัง OCR เรียกแปลจริงทั้ง Google และ AI แบ่งชุด ตรวจ ID ผลตอบกลับ ลองกรอบที่ตกหล่นซ้ำ และระบุกรอบที่ไม่สำเร็จ
- ถ้าแก้ข้อความหรือกรอบหลังแปล OCR Lab แจ้งให้แปลใหม่ โดยเก็บ OCR ดิบเดิมไว้
- ตรวจอักษรภาษาปลายทางและลองกรอบที่ส่งกลับผิดภาษาซ้ำ หากยังผิดจะบันทึกเป็นไม่สำเร็จ การตรวจนี้ไม่ได้วัดความถูกต้องเชิงความหมาย
- LM Studio: ตรวจ API/ความสามารถจริง แล้วใช้ /api/v1/chat พร้อม reasoning off เมื่อโมเดลรองรับ เพื่อไม่ให้โทเคนหมดไปกับ reasoning โดยไม่มีคำแปล ตาม https://lmstudio.ai/docs/developer/rest/chat ส่วนเซิร์ฟเวอร์ที่ไม่มี API นี้ยังใช้ chat completions เดิม
- ทดสอบตัวเชื่อม: npm run test:translation; ทดลองผู้ให้บริการจริงจากผล OCR ที่บันทึกไว้: npm run test:translation:live


## OCR 1.6.34 — ค้นหาข้อความเพิ่มและเทียบภาพปรับแต่ง

- เอนจินใหม่ค้นหาด้วย CTD และ Paddle PP-OCRv5 server detector แยกกัน ทั้งภาพเดิมและ CLAHE; ภาพหน้าปกติที่ใหญ่กว่า 1536 px เพิ่มภาพย่อย 1024 px ซ้อนทับอย่างน้อย 20% ภาพยาวยังใช้ภาพย่อยซ้อนทับและเพิ่มรอบทั้งหน้า
- Paddle ที่พบเพิ่มเป็นข้อเสนอซึ่งต้องยืนยันคำอ่านก่อนรับเข้า ผลที่ไม่ผ่านและผลดิบยังเก็บไว้ตรวจ กรอบที่คร่อมหลายชุดเดิมจะไม่รวมอัตโนมัติ เทียบตำแหน่งบรรทัดเพื่อกันกรอบซ้ำจาก padding ของสอง detector
- อ่านจากภาพเดิม ระดับเทา คอนทราสต์ กลับดำ–ขาว CLAHE Adaptive threshold และ Otsu เลือก “อ่านซ้ำเมื่อไม่ชัด” หรือ “เทียบภาพทุกแบบ” ใน OCR Lab กรอบที่ไม่แน่ใจลอง padding/ขนาดใหม่ และยังแสดงความขัดแย้งให้ตรวจ
- ปุ่ม “ดูภาพที่ใช้ OCR” เปิดภาพ crop ของแต่ละคำอ่าน รวม padding และพื้นที่แยกข้อความจริง ตำแหน่งกรอบ/บรรทัด/polygon ของทุกทางเลือกกลับไปเป็นพิกเซลต้นฉบับ แม้ใช้ 2×/3× หรือเปลี่ยนขนาด crop
- แยกบอลลูนพื้นสี/ไล่สีจากขอบ และบอลลูนที่เชื่อมกว้างจากรอยเว้าสองข้าง โดยต้องมีช่องว่างระหว่างบรรทัดและข้อความพอทั้งสองฝั่ง เก็บย่อหน้าเดียวในวงรีไว้ร่วมกัน
- อ่านมังงะญี่ปุ่นด้วย Manga OCR; ข้อเสนอใหม่ที่ไม่แน่ใจต้องมี OCR ญี่ปุ่นอีกตัวสนับสนุน เพื่อลดคำอ่านที่สร้างจากภาพไม่มีข้อความ
- ชุดทดสอบทั้งหน้าพร้อมภาพต้นฉบับและเฉลยอยู่ใน `test-results/ocr-advanced/`; เฉลยมังงะจริงยังเป็นบางส่วน ส่วนหน้าไทยใหม่เป็นภาพสร้างสำหรับควบคุมการทดสอบ ไม่ใช่มังงะจริงอิสระ การสแกนละเอียดใช้เวลาเพิ่มและยังไม่ยืนยันความแม่นยำ 99% ทั้งชุด โดยเฉพาะ SFX

## OCR 1.6.33 — ภาพครอปและกรอบข้อความไทย

- ลดการขยายก่อน CTD เมื่อภาพเล็กจะถูกขยายเกิน 2×; การขยาย 1×/2×/3× ใน Lab ยังอ้างอิงขนาดต้นฉบับเมื่อเลือกสเกลตรวจ เพื่อไม่ให้แยกข้อความเดียวเพราะตัวอักษรใหญ่เกินไป
- รวมข้อเสนอกรอบที่ใช้บรรทัดจริงซ้ำกัน โดยต้องมีแนวและพื้นที่ทับกันรองรับ ไม่รวมบอลลูนข้างเคียงจากระยะใกล้อย่างเดียว
- เพิ่มพื้นที่รอบ crop ภาษาไทยสำหรับวรรณยุกต์ และใช้ตำแหน่งบรรทัดที่อ่านได้ปรับกรอบวางทับ เก็บ detectorBBox เดิมไว้ตรวจสอบ
- แสดงรุ่นแอปและรุ่นของแต่ละรอบ OCR; ระบุกรอบที่แยกด้วยมือในรายละเอียด ผลเก่าที่ไม่มีเลขรุ่นจะแสดงว่าไม่ทราบรุ่น
- ชุดทดสอบภาพเดียวกันหลาย crop/scale เป็นการทดสอบการถดถอย ไม่ใช่หลักฐานความแม่นยำ 99% ทั้งชุดมังงะ

## OCR 1.6.32 — เปรียบเทียบเอนจินและแยกลูกโป่งเชื่อมกัน

- OCR Lab เลือกเอนจินใหม่ (Manga OCR สำหรับญี่ปุ่น / PaddleOCR PP-OCRv5 สำหรับอังกฤษ ไทย และฝรั่งเศส) หรือฐานเดิม Tesseract ได้ เก็บผลแต่ละรอบและคำอ่านทางเลือกไว้ตรวจเทียบโดยไม่แก้ผลดิบ
- อ่านหลายรูปแบบภาพ จัดลำดับบรรทัดเอียง ตัดเศษอักขระซ้ำที่ทับบรรทัดหลัก และเทียบคำอ่านทีละบรรทัด กรอบที่คำอ่านขัดกันยังขึ้นให้ตรวจ Manga OCR ไม่มีคะแนนความมั่นใจ จึงแสดงว่าไม่มีคะแนน
- แยกพื้นที่ขาวที่มีขอบและลูกโป่งสองส่วนที่เชื่อมด้วยคอแคบ รองรับการหมุนแนวตั้ง และกันเศษข้อความจากกรอบข้างเคียงด้วยพื้นที่แต่ละบรรทัด ผลแยกอัตโนมัติยังต้องตรวจในภาพยาก
- ชุดเฉลย 60 กรอบรวมกรอบไม่มีข้อความ 2 กรอบ ชุดทดสอบอังกฤษ/ญี่ปุ่นคนละหน้ากับชุดปรับระบบ 19 กรอบ: ตัวอักษรถูก 79.15% → 98.51% และตรงทั้งกรอบ 15/19 ตัวเลขนี้วัดเฉพาะคำอ่านในกรอบ ไม่ใช่ความครบหรือตำแหน่งทั้งหน้า และยังไม่ยืนยัน 99% ของทั้ง 515 ภาพ
- รายงาน `test-results/engine-comparison/report.md`; เปิด `comparison-review.json` ใน OCR Lab เพื่อตรวจภาพ เฉลย และทางเลือก ระบบแสดงว่าเป็นเฉลยคำอ่านและไม่เปิดให้ยืนยันความครบทั้งภาพ
- เอนจินเสริมประมวลผลบนเครื่อง ใช้ runtime ที่ `%LOCALAPPDATA%\ImageHarvest\ocr-runtime` และดาวน์โหลดโมเดลสาธารณะครั้งแรก ติดตั้ง runtime ด้วย `scripts/setup-ocr-runtime.ps1 -Python <Python 3.12 path>`; ไม่รวม Python และน้ำหนักเสริมในตัวติดตั้งแอป หาก runtime ไม่มี ระบบแจ้งข้อผิดพลาดชัดเจน
- เมื่อทราบภาษาต้นฉบับ ให้เลือกภาษานั้นใน OCR Lab การอ่านหลายรูปแบบและการตรวจเทียบใช้เวลามากกว่าฐานเดิม

เอนจินอ้างอิง: [Manga OCR](https://github.com/kha-white/manga-ocr), [PaddleOCR PP-OCRv5](https://www.paddleocr.ai/latest/en/version3.x/algorithm/PP-OCRv5/PP-OCRv5_multi_languages.html). การทดสอบ: `npm run test:ocr`, `npm run test:ocr-lab`; สร้างข้อมูลด้วย scripts/prepare-ocr-reference.cjs, verify-ocr-reference.cjs, prepare-ocr-holdout.cjs, freeze-ocr-holdout.cjs, compare-ocr-engines.cjs และ report-ocr-comparison.cjs ตามลำดับ เฉลยบางชุดต้องใช้ภาพต้นฉบับของเครื่องทดสอบนี้

## OCR 1.6.30 — ภาพยาวและ AVIF

## OCR Lab — ตรวจข้อความและตำแหน่ง

เปิด **ทดสอบ OCR** จากเมนูด้านซ้าย หรือเปิด OCR Lab ในแผงแปลของ HarvestTS

- นำเข้าหลายภาพ, วางภาพจาก Clipboard, แคปแท็บ HarvestTS หรือเปิดผล Harvest ล่าสุด เมื่อแคปแท็บจะซ่อนปุ่มแปลชั่วคราวและบันทึก URL, scroll และขนาด viewport ของภาพ
- เลือกญี่ปุ่น / อังกฤษ / ฝรั่งเศส / ไทย และโหมดตรวจบริเวณข้อความมังงะ, แนวนอน หรือแนวตั้งญี่ปุ่น ขยายภาพก่อน OCR ได้ 1× / 2× / 3× พิกัดที่ส่งกลับยังใช้พิกเซลภาพต้นฉบับ
- เลือกกรอบบนภาพเพื่ออ่านข้อความ วาดกรอบที่ตกหล่น แก้พิกัด แยกซ้าย/ขวาหรือบน/ล่าง และ OCR เฉพาะกรอบได้
- ผล OCR ดิบและผลแต่ละรอบแยกจากผลที่แก้ไข เลือกผลรอบใดมาเป็นผลที่ตรวจได้ กรอบความมั่นใจต่ำหรือขัดแย้งกันต้องตรวจจากภาพ
- สร้างเฉลยอ้างอิงแยกแต่ละชุดข้อความ ตรวจข้อความและกรอบทุกชุด แล้วเลือก “ตรวจเฉลยครบทั้งภาพแล้ว” การคัดลอก OCR เป็นร่างเฉลยยังไม่ใช่การตรวจความครบ
- คะแนนพบข้อความใช้การจับคู่กรอบหนึ่งต่อหนึ่งที่ IoU ≥0.5; คะแนนตำแหน่งนับกรอบที่ IoU ≥0.8 ตัวอักษรใช้ edit distance หลังปรับ Unicode และช่องว่าง ไม่ใช่ confidence ของเอนจิน
- ผ่านเป้าหมายเฉพาะภาพที่มีเฉลยยืนยันครบ และ recall, precision, localization recall, character accuracy ≥99% โดยไม่มีกรอบรวม/แยกผิด คะแนนหลังแก้ไขด้วยมือไม่ใช่คะแนน OCR อัตโนมัติ ให้เลือกผล OCR ดิบเพื่อวัดเอนจิน
- บันทึกโปรเจกต์ JSON พร้อมภาพต้นฉบับ, SHA-256, ผล OCR, แต่ละรอบ, เฉลย และพิกัด รองรับการตรวจชนิด bubble / unboxed / sfx และเก็บ translation ที่มีอยู่จาก Harvest

นี่คือฐาน OCR และระบบทดสอบสำหรับพัฒนาระบบแปลมังงะ ขั้นตรวจเส้นขอบกล่องคำพูด, ลบข้อความบนพื้นผิวภาพ, แปลด้วยภาพประกอบ และวางคำแปลบนเว็บยังต้องพัฒนาต่อ ไม่มีการรับรองความแม่นยำ 99% บนมังงะทุกเรื่องจากชุดทดสอบขนาดเล็ก

ทดสอบ: `npm run test:ocr` และ `npm run test:ocr-lab` · เปิด Lab ตอนเริ่มแอป: `npm start -- --ocr-lab`

แอป Windows สำหรับรวบรวมไฟล์ภาพจากหน้าเว็บ ดูตัวอย่าง กรอง จัดลำดับ และบันทึกไฟล์ต้นฉบับลงเครื่อง รวมโหมดจับเว็บที่เปลี่ยนทีละหน้าโดยให้ผู้ใช้กดเปลี่ยนหน้าเอง

## วิธีใช้งาน
ค่าเริ่มต้นคือ **Google Chrome** พร้อม **รองรับระบบป้องกันที่รู้จักอัตโนมัติ**; ต้องติดตั้ง Chrome ในเครื่องก่อน ไม่มีการดาวน์โหลดเบราว์เซอร์เงียบ ๆ หากต้องการใช้ตัวเดิม เลือกเบราว์เซอร์ในแอปได้

1. วาง URL แล้วกด **สแกนภาพ** หรือกด **เปิดเว็บ** เพื่อดู/ล็อกอินก่อน
2. เลือกภาพ กรองขนาดขั้นต่ำ และเรียงตามตำแหน่งบนหน้า / DOM / ชื่อไฟล์ / ลากเอง
3. ถ้าต้องการเก็บหลายตอนต่อกัน ให้เปิด **ไล่ตอนถัดไปอัตโนมัติ** แล้วใส่เลขโฟลเดอร์เริ่มต้น เช่น `7`; แอปจะบันทึกตอนแรกลง `7`, หา Next Chapter แล้วใช้ `8`, `9` ต่อไปจนหา Next ที่มั่นใจไม่ได้หรือผู้ใช้กดหยุด
4. เว็บที่ต้องเปลี่ยนหน้าภายในตอนเองสามารถใช้ **จับทีละหน้า** แล้วกด Next/ลูกศรในหน้าต่างเว็บ ระบบจะสะสมภาพใหม่ให้
5. เลือกโฟลเดอร์ปลายทาง แล้วกด **บันทึกภาพที่เลือก** หรือ **เริ่มเก็บต่อเนื่อง**

โหมดปกติ: ถ้ากรอกชื่อโฟลเดอร์ชุดภาพ เช่น `1` แอปจะสร้างโฟลเดอร์ชื่อ `1` ตรง ๆ; ถ้ามีอยู่แล้วจะเป็น `1-2`, `1-3` ฯลฯ
โหมดไล่ตอน: ใช้เลขโฟลเดอร์ตรง ๆ และ **ไม่เติม suffix**; ถ้ามีโฟลเดอร์เลขนั้นอยู่แล้ว ระบบจะหยุดเพื่อกันชุดตอนเหลื่อมหรือทับของเดิม
ถ้าปล่อยชื่อว่าง จึงค่อยใช้ชื่อหน้าเว็บพร้อมเวลาอัตโนมัติ
ชื่อไฟล์เป็น `0001.png`, `0002.webp` ฯลฯ ตามลำดับของภาพที่เลือกและผ่านตัวกรอง ณ เวลากดบันทึก
แอปไม่แปลงชนิดไฟล์และไม่บีบอัดต้นฉบับซ้ำ และมี `report.json` ระบุผลสำเร็จ/ล้มเหลว

## รองรับใน V1
- IMG และ currentSrc ของ picture/srcset ที่เบราว์เซอร์เลือกใช้
- Lazy loading ผ่านการเลื่อนอัตโนมัติ และ data-src/data-original/data-lazy-src/data-url ที่พบบ่อย
- ภาพพื้นหลัง CSS แบบ url(...), open shadow DOM และพื้นที่อ่านแบบเลื่อนภายในหน้า
- ภาพ data URL และ blob URL ที่ยังเข้าถึงได้จากหน้าเดิม
- JPG, PNG, WebP, AVIF, GIF, BMP, ICO และ SVG
- ซ่อนรูปที่มี URL ซ้ำ และจัดลำดับด้วยการลาก/ลูกศร
- ตั้ง CSS selector ของส่วนเนื้อหา, เวลารอ lazy load และจำนวนรอบเลื่อนสูงสุด
- หยุดสแกนโดยเก็บผลที่พบไว้ และหยุดบันทึกโดยไม่ลบไฟล์ที่เสร็จแล้ว
- ปุ่ม **กลับลำดับ** พลิกลำดับภาพที่สแกนได้ทั้งชุดในคลิกเดียว
- เครื่องมือ **ตั้งเลขหน้ารูป** สำหรับโฟลเดอร์ในเครื่อง: เรียงชื่อตามตัวเลข เลือกปกติ/ย้อนกลับ แล้วเปลี่ยนชื่อเป็น `0001`, `0002`… แบบสองขั้นตอนเพื่อลดปัญหาชื่อชนกัน
- **รวม Canvas**: รอ Canvas ที่ถูกวาดจริงระหว่าง auto-scroll แล้วบันทึกเป็น PNG; Canvas ที่ browser ป้องกันการอ่านพิกเซลจะไม่ถูกข้ามข้อจำกัด

## ข้อจำกัดสำคัญ
- สแกนปกติทำงานกับ **หน้า URL ปัจจุบัน** และไม่คลานทั้งเว็บไซต์หรือกดไปตอนถัดไปเอง; โหมด **จับทีละหน้า** รองรับการสะสมหลายหน้าที่ผู้ใช้กดเปลี่ยนเอง แต่ยังไม่เดาปุ่ม Next ของแต่ละเว็บอัตโนมัติ
- Canvas capture เก็บเฉพาะผลลัพธ์ที่หน้าเว็บวาดและ browser อนุญาตให้อ่านแล้ว ไม่ถอดรหัสไฟล์ต้นทางเอง; ยังไม่สแกนภายใน iframe
- บางเว็บที่เป็น virtualized layout หรือเปลี่ยนตำแหน่งภาพตลอด อาจต้องปรับลำดับเอง
- `srcset` ใช้ภาพที่ Chromium เลือกจริง ไม่เดาว่ารูปใดเป็นต้นฉบับใหญ่ที่สุด
- จำกัด 5,000 occurrences ต่อสแกน, 32 MB ต่อภาพ และแคชไฟล์ภาพในหน่วยความจำไม่เกิน 128 MB
- เลื่อนอัตโนมัติสูงสุด 600 รอบ ไม่ข้าม paywall, CAPTCHA หรือการจำกัดการเข้าถึง
- Cookie/login ใช้เฉพาะเบราว์เซอร์แยกของแอป; Chrome ใช้โปรไฟล์ชั่วคราวบนดิสก์และล้างเมื่อปิดตามปกติ ไม่ยืม cookie ของ Chrome/Edge ส่วนตัว
- เว็บที่ต้องใช้ popup เพื่อเข้าสู่ระบบอาจใช้ไม่ได้ใน V1 เพราะแอปบล็อก popup
- URL ใน report/links อาจมี token ที่เว็บไซต์ใส่มา ไม่ควรเผยแพร่ไฟล์เหล่านี้โดยไม่ตรวจสอบ

- **คืนรายการล่าสุด**: ย้อนการนำออกครั้งล่าสุด รวมลำดับและสถานะการเลือก ใช้ได้ก่อนสแกนใหม่หรือล้างทั้งหมด
- **ล้างทั้งหมด**: ล้างผลสแกนรวมภาพที่ซ่อน ประวัติคืนรายการ แคช และไฟล์ Canvas ชั่วคราว โดยคง URL/โฟลเดอร์ปลายทาง
- ทั้งสามคำสั่งนี้ไม่ลบหรือแก้ไขไฟล์ที่ดาวน์โหลดไปแล้ว และใช้ไม่ได้ระหว่างสแกนหรือบันทึก
- หลังนำบางรายการออก แคชและไฟล์ Canvas ของรอบสแกนยังอาจคงอยู่ชั่วคราวเพื่อคืนรายการ และถูกล้างเมื่อกดล้างทั้งหมด/สแกนใหม่/ออกจากแอปตามปกติ

ตัวกรองใหม่ปิดไว้โดยค่าเริ่มต้น และเป็นเพียงการซ่อน ไม่ได้ลบผลสแกน:
- **ซ่อนโลโก้ / รูปประกอบเว็บ**: ประเมินจากชื่อไฟล์ alt/class และบริเวณเมนู โฆษณา คอมเมนต์ รูปแนะนำหรือรูปโปรไฟล์
- **เฉพาะเนื้อหาหลัก**: เลือกเขตตัวอ่านที่รู้จักก่อน แล้วจึง main/article หากไม่พบเขตหลักจะเตือนและคงภาพที่ไม่แน่ใจไว้
- **ชนิดภาพ**: เลือกทั้งหมด, IMG, Canvas หรือภาพพื้นหลังได้
- **รีเซ็ตตัวกรอง**: คืนค่าตัวกรอง โดยยังซ่อน URL ซ้ำและไม่คืนรายการที่กดนำออก
- บันทึกเฉพาะรายการที่เลือกและผ่านตัวกรองตามลำดับบนหน้าจอ ณ เวลากดบันทึก

นี่เป็นกฎประเมินจากข้อมูลและโครงสร้างหน้าเว็บ ไม่ใช่ AI อ่านเนื้อหาภาพ จึงอาจคัดผิดได้
หน้าโฆษณาที่แทรกอยู่ในตัวอ่านเหมือนหน้าปกติอาจยังผ่าน ต้องตรวจและเลือกนำออกเอง
การกรองโลโก้คือการซ่อนไฟล์ที่เป็นโลโก้ ไม่ใช่การลบลายน้ำที่ฝังอยู่ในภาพ

## DNS / Network compatibility (1.0.6)
เลือกโหมดเครือข่ายได้จากหน้าแอป: **อัตโนมัติ**, **Cloudflare DNS**, **Google DNS**, **AdGuard DNS** และ **Compatibility**

- Cloudflare/Google ใช้ DNS-over-HTTPS ใน Electron และใช้ resolver ที่เลือกกับการดาวน์โหลดภาพของ Chrome mode ด้วย
- Compatibility ใช้ Cloudflare DNS และปิด HTTP/2 + QUIC; ต้องรีสตาร์ตแอปเพราะ Chromium ต้องรับ flags ก่อนเริ่มทำงาน
- เมื่อพบ `ERR_HTTP2_PROTOCOL_ERROR` แอปจะแนะนำ Compatibility; timeout/name-resolution จะแนะนำ Cloudflare/Google
- ตัวเลือกเหล่านี้ช่วยแก้ความเข้ากันได้ของเครือข่าย ไม่ได้ข้าม HTTP 403, CAPTCHA, paywall หรือข้อจำกัดสิทธิ์ของเว็บไซต์

### Smart Auto (1.0.8)
- โหมด **อัตโนมัติ** ใช้ Secure DNS ของ Cloudflare เป็นทางหลักและ Google เป็นสำรอง เพื่อลดปัญหา DNS ของเครือข่ายชี้ไปปลายทางที่ timeout
- ระบบสลับสำรองเฉพาะ timeout / name-resolution / network-unreachable; ไม่ retry เพื่อข้าม HTTP 403, CAPTCHA หรือ access challenge
- จำ DNS ที่ใช้ได้ต่อโดเมนใน session ปัจจุบัน เพื่อลดการลองซ้ำ และยังเลือก Cloudflare / Google / Compatibility เองได้
- ทดสอบตัวแพ็กกับ URL ที่ผู้ใช้รายงาน: Hitomi เปิดได้ทั้งหน้าเรื่องและ reader; nhentai gallery เปิดได้ ส่วนหน้าที่เว็บตอบ `Just a moment...` ยังคงรายงานเป็น access gate

### AdGuard DNS + reader แบบทีละหน้า (1.0.9)
- เพิ่ม **AdGuard DNS** เป็นตัวเลือกแยกแบบ opt-in ใช้ AdGuard Public DNS โหมด Default สำหรับบล็อกโฆษณาและตัวติดตาม ไม่ใช่ Family mode
- หากเว็บพึ่งพาโดเมนที่ถูก AdGuard กรองจนโหลดไม่ครบ ให้กลับ **Smart Auto**; แอปไม่บังคับเปิด AdGuard ให้เอง
- โหมด **จับทีละหน้า** เป็น event-driven สำหรับ reader ที่เปลี่ยนหน้าด้วย URL hash/history หรือสลับ IMG source และยังมี polling สำรองสำหรับ Canvas
- สแกนปกติยังเก็บเฉพาะหน้าปัจจุบัน; เว็บที่แสดงทีละหน้าให้กด **จับทีละหน้า** แล้วใช้ปุ่ม Next/ลูกศรของเว็บ
- Live test Hitomi `reader/19324.html#2`: ตั้ง polling fallback 3,000 ms แต่ตัวแพ็ก 1.0.9 จับหน้าหลังคลิก Next ได้ประมาณ 210 ms จึงยืนยันว่าตื่นจาก page/image change จริง

## ประวัติ Google Chrome mode 1.0.5
Choose **Google Chrome จริง (ทดลอง)** above the URL, then open or scan the page.
This mode runs the installed Google Chrome in a visible window through Playwright/CDP.
The DevTools panel is not opened. Browser security settings remain enabled.
Site scripts are left unchanged unless the opt-in site-compatibility option below is enabled.

- Chrome must already be installed. There is no silent browser download or fallback to another brand.
- A fresh, temporary ImageHarvest profile is created. Personal Chrome profiles and their cookies are never imported.
- Log in manually inside the app-created Chrome window when authorized. Closing ImageHarvest closes this Chrome instance and removes its temporary profile.
- Image downloads use only cookies from this app-created session, keep the size limit, and stop at HTTP 403/429 rather than bypassing access checks.
- Extra popup tabs are closed in this initial implementation; popup-based login may not work.
- Canvas collection keeps the browser's origin-clean checks. Tainted Canvas is not exported.
- A website may still reject automation or navigate away even when no DevTools panel is visible. Chrome mode does not guarantee access to every website.
- The default embedded browser remains available. This release does not include a Chrome extension.

`playwright-core` is now a production dependency for Chrome mode, in addition to its test usage.
Run `npm.cmd run test:chrome` on a Windows machine with Google Chrome installed.
The local fixture verifies lazy Canvas capture while a dimension-based inspect detector continues running.
It is a synthetic test, not a clone of any third-party site's complete protection system.
API references: https://playwright.dev/docs/api/class-browsertype ; https://playwright.dev/docs/api/class-cdpsession

## ประวัติ 1.0.10 — โหมดเฉพาะเว็บ (ถูกแทนที่ใน 1.1.0)

ติ๊ก **โหมดเฉพาะ NTRNaja / Pengi** ก่อนเปิด URL; แอปจะเลือก Google Chrome จริงให้โดยอัตโนมัติ
โหมดนี้ปิดเป็นค่าเริ่มต้น บันทึกตัวเลือกไว้ในเครื่อง และมีผลเฉพาะโดเมนที่ระบุตรงตัวเท่านั้น

- NTRNaja: ยกเลิกเฉพาะคำขอสคริปต์ตรวจจับสองรายการที่ตรวจไว้ ไม่บล็อก CDN ทั้งโดเมน
- Pengi: ตรวจ SHA-256 ของ reader bundle ก่อนปรับเฉพาะจุดเริ่ม detector และ callback ที่ทำให้แท็บค้าง
  ส่วน reader, การตรวจสิทธิ์, API, ลายน้ำ และ MutationObserver เดิมไม่ถูกแก้
- หาก Pengi เปลี่ยน bundle ที่ตรวจพบ จะหยุดและแจ้งให้อัปเดตกฎ ไม่พยายามแทนโค้ดแบบเดาสุ่ม
- ตัวเลื่อนใช้ `scrollTo/scrollBy` แบบ instant โดยไม่เขียน inline style ของหน้าเว็บ
- เก็บต้นฉบับจาก image response ที่ Chrome ได้รับสำเร็จแล้ว และผูกกลับกับลำดับภาพใน DOM
- ในโหมดเฉพาะเว็บ ภาพ HTTP ที่ Chrome ยังไม่ได้โหลดสำเร็จจะรายงานว่าขาดข้อมูล ไม่ยิง HTTP client ซ้ำ
- แคช response จำกัด 32 MiB ต่อภาพ และ 512 MiB ต่อเซสชัน; ใช้โปรไฟล์ชั่วคราวของแอปและล้างเมื่อปิด
- ชุดภาพที่สแกนสำเร็จมี snapshot แยกสำหรับ Preview/Export และ `report.json` มี SHA-256 กับวิธีรับภาพ
- ไม่มีการแก้ response 401/403/429 เป็นสำเร็จ ไม่แก้ CAPTCHA, การล็อกอิน, หรือสิทธิ์ซื้อตอน
- หน้าเว็บยังอาจเปลี่ยนโครงสร้างหรือเงื่อนไขการเข้าถึงได้; ไม่รับประกันทุกตอนหรือทุกเว็บไซต์

ทดสอบกฎและการเก็บ response ด้วย `npm test` และ `npm run test:sites`
การทดสอบเว็บจริงแยกอยู่ใน `test-results/` ซึ่งไม่ส่งขึ้น Git และไม่เป็นส่วนหนึ่งของ regression อัตโนมัติ


## 1.1.0 — Generic Protection Compatibility

- ไม่ตรวจ hostname หรือชื่อไฟล์เพื่อเลือกกฎอีกต่อไป ตรวจเนื้อหาสคริปต์ HTTP(S) ที่ Chrome ได้รับ ก่อนรัน
- รู้จัก 3 ลายเซ็น SHA-256 ที่ตรวจแล้ว: disable-devtool 0.3.9 UMD, devtools-detect fork 2.1 ESM และ integrated reader build ที่ตรวจเมื่อ 18 ก.ย. 2026
- รองรับการย้ายไฟล์เดิมไปโดเมน/เส้นทางใหม่โดยไม่เพิ่มรายชื่อเว็บ แต่ไม่ใช่รองรับทุกเวอร์ชันในตระกูลนั้น
- ถ้าเนื้อหาเปลี่ยนแม้ชื่อ library เหมือนเดิม: ไม่ patch อัตโนมัติ รายงาน unknown แล้วปล่อยโค้ดเดิมตามปกติ
- ข้อยกเว้นด้านความปลอดภัย: ถ้าพบร่องรอยชุดจัดสรรหน่วยความจำอันตรายที่ยังไม่ตรงกฎ จะระงับสคริปต์และหยุดสแกนให้ตรวจใหม่ ไม่เดาแก้ และไม่ใช่เครื่องมือตรวจ malware ครบทุกชนิด
- กฎ standalone คง API/default export ที่ตัวเรียกต้องใช้ แทนการบล็อกไฟล์จน dependency หาย
- รายละเอียดการตรวจมี family, rule ID และ hash; URL diagnostic ตัด query/fragment/credentials ออก ไม่บันทึก cookie หรือ body สคริปต์
- ปุ่มเปิดอัตโนมัติยังปิดได้ และจำค่าที่ผู้ใช้เลือก; ตัวเลือกเฉพาะสองเว็บเดิมเลิกใช้แล้ว
- Chrome เก็บ successful image response ทุกเว็บ ไม่ขึ้นกับว่าพบ protection หรือเปิด engine ไว้หรือไม่ รองรับ URL redirect alias และ snapshot ยังอยู่หลังปิด Chrome
- ใช้ไฟล์ snapshot ที่ hash เหมือนกันร่วมกัน ลดการเก็บภาพซ้ำ; แคช response จำกัด 32 MiB/ภาพ และ 512 MiB/เซสชัน
- การวิเคราะห์สคริปต์มีเพดาน 2 MiB/ไฟล์, 300 ไฟล์ และประมาณ 32 MiB/เอกสาร; ไม่ใช่การตรวจทุกไบต์ของทุกเว็บ
- เมื่อเปิดการรองรับอัตโนมัติ จะไม่ให้ Service Worker เริ่มในโปรไฟล์ชั่วคราวของแอป เพื่อไม่ให้ข้ามการตรวจคำขอ; เว็บไซต์ที่พึ่ง PWA/Service Worker อาจต้องปิดตัวเลือกนี้และเปิดหน้าใหม่
- ไม่แก้ inline script, worker/OOPIF ทุกบริบท หรือไฟล์ที่เกินขอบเขตการตรวจ ไม่ปิด CSP/CORS/SRI ไม่รับประกันเว็บที่ใช้ integrity หรือ reader พึ่ง detector แตกต่างจากที่ทดสอบ
- ไม่แก้ CAPTCHA, login, entitlement หรือเปลี่ยน HTTP error เป็น success; unknown server challenges คงเดิม

Tests: `npm test`, `npm run test:protection`, `npm run test:sites` และ regression suites เดิม
ชุด test:protection ต้องมีสำเนา OSS สองไฟล์จากผลตรวจที่ hash ตรงใน test-results; ไม่ส่ง reader bundle ของเว็บอื่นขึ้น Git

## 1.2.0 — Chrome Minimal

เพิ่มตัวเลือก **วิธีควบคุม → Minimal — ไม่แก้สคริปต์เว็บ** ข้างตัวเลือก Google Chrome โหมด Standard เดิมยังอยู่และยังเป็นค่าเริ่มต้นเมื่อไม่มีการตั้งค่าไว้; การอัปเดตเครื่องเจ้าของครั้งนี้เลือก Minimal ให้โดยสำรอง settings เดิมก่อน

Minimal เปิด Chrome ที่ติดตั้งแล้วด้วยโปรไฟล์ชั่วคราวแยก และสั่งงานผ่าน raw CDP โดยไม่ attach Playwright ไปยังหน้าอ่าน ไม่เปิดแผง DevTools และไม่เรียก Runtime.enable / Console.enable / Debugger.enable ระหว่างอ่าน แต่ยังใช้ Runtime.evaluate กับ Network สำหรับ DOM/Canvas และเก็บ image response ที่โหลดสำเร็จ จึงไม่ควรเรียกโหมดนี้ว่า “ไม่ใช้ CDP”

- Minimal ไม่ติดตั้ง ProtectionCompatibility, ไม่แก้หรือบล็อกสคริปต์ detector และไม่สลับไปใช้กฎ Standard เอง
- ตัวเลือกแก้สคริปต์ของ Standard จะถูกปิดไม่ให้กดขณะใช้ Minimal แม้ค่าที่บันทึกเดิมยังติ๊กไว้
- Canvas เก็บเป็น PNG จากพื้นผิวที่วาดแล้ว; ไม่อ้างว่าเป็นไฟล์อัปโหลดต้นฉบับทุกไบต์ และยังเคารพ SecurityError ของ tainted Canvas
- ใช้คิว Preview/Export, ลำดับภาพ, DNS และตัวกรองเดิม; ไม่เปลี่ยนระบบสิทธิ์เว็บไซต์หรือปิด CSP/CORS
- Chrome เปิดเป็นหน้าต่างจริง; รอ reader เริ่มทำงานก่อนกดสแกนสำหรับเว็บที่โหลดช้า และเลือก “รวม Canvas” สำหรับเว็บที่วาดภาพด้วย Canvas
- ไม่มีผลรับรองกับทุกเว็บไซต์/เวอร์ชัน และผลเดิมของ Standard ไม่ใช่หลักฐานว่า Minimal ผ่านเว็บไซต์เดียวกัน

ทดสอบในเครื่องด้วย npm run test:minimal (fixture สังเคราะห์) และ npm run test:chrome (Standard) รายละเอียดผลจริงของรุ่นนี้อยู่ท้าย TESTED.md


## 1.3.0 — Workspace Tabs + Pre-read

- เพิ่มแท็บงานสูงสุด 12 แท็บ แต่ละแท็บเก็บ URL, ผลสแกน, ลำดับ, การเลือก และตัวกรองแยกกัน สลับกลับมาแล้วรายการเดิมไม่หาย
- งานสแกน/จับภาพยังทำทีละแท็บที่กำลังใช้งาน เพื่อไม่ให้หลายแท็บแย่ง browser/session เดียวกัน; การมีหลายแท็บมีไว้เตรียมและพักหลายลิงก์พร้อมกันโดยไม่ล้างคอลเลกชันเดิม
- เพิ่ม **Pre-read** สำหรับภาพที่เลือกและกำลังแสดง: โหมดมังฮวาต่อภาพชิด 0 px และโหมดมังงะเว้นช่องระหว่างหน้า พร้อมเลือกความกว้างได้
- Pre-read เป็นตัวอ่านต่อเนื่องในแอป ไม่สร้างไฟล์ภาพยักษ์ใหม่ และไม่เปลี่ยนไฟล์ต้นฉบับ
- ระบบกรองขั้นถัดไปและเครื่องมือประกอบภาพทีถูกแบ่งยังแยกเป็นงานถัดไปตาม roadmap


## 1.4.0 — Context filters + progressive results

- ปรับตัวกรองโลโก้/ไอคอนจากชื่อไฟล์, alt, ขนาดที่แสดงจริง และบริบทปุ่มควบคุม จึงแยกโลโก้ Google ที่ไฟล์ใหญ่แต่แสดงเล็ก และไอคอนชำระเงินได้ โดยไม่ซ่อน SVG ทั้งหมด
- แยกโฆษณาจากบริเวณที่ระบุชัด หรือแบนเนอร์พร้อมลิงก์ออกนอกเว็บไซต์ ไม่ตัดสินจากอัตราส่วนภาพหรือ CDN ต่างโดเมนเพียงอย่างเดียว และไม่เปิดลิงก์โฆษณา
- ซ่อน placeholder/ภาพรอโหลด/ป้ายตัวอ่านที่รู้จักจากชื่อที่มีบริบท; หากภาพรอโหลดเปลี่ยนเป็นหน้าจริงระหว่างสแกน หน้าจริงยังถูกเก็บตามปกติ
- เฉพาะเนื้อหาหลักเลือกกลุ่มตัวอย่างหนังสือก่อนส่วนอื่นของหน้าสินค้า รองรับตัวอย่าง BookWalker ขนาด 157 × 224 โดยไม่เปลี่ยนขนาดขั้นต่ำเป็น 300 px
- เพิ่ม **ซ่อนหน้าว่าง / สีล้วน (คาดว่า)** แยกต่างหากและปิดเป็นค่าเริ่มต้น ตรวจพิกเซลตัวอย่าง PNG/JPEG/Canvas จากข้อมูลที่แอปรับมาแล้วในเครื่อง ไม่แก้ต้นฉบับ ไม่ใช่ AI/OCR และไม่ปลดข้อจำกัด Canvas ของเว็บไซต์
- การตรวจหน้าว่างเป็น heuristic: หน้าที่มีเนื้อหาจาง/เล็กอาจคัดผิดได้ และหน้าว่างจริงอาจเป็นส่วนหนึ่งของหนังสือ ปิดตัวเลือกเพื่อคืนรายการ; ผลที่ยังอ่าน/ตรวจไม่ได้คงไว้ ไม่ลบทิ้ง
- ผลสแกนทยอยเข้ารายการเป็นชุดเล็ก พร้อมรูปเมื่อมีข้อมูล ไม่ต้องรอสแกนจบ ปุ่มจัดการรายการยังใช้เงื่อนไขเดิมระหว่างงาน และหยุดสแกนแล้วยังเก็บผลบางส่วนไว้
- Chrome ไม่ยิงคำขอ Preview ซ้ำขณะกำลังรอเว็บโหลดภาพระหว่างสแกน; ภาพที่ยังไม่พร้อมแสดงข้อความรอ เมื่อมี snapshot จึงแสดงภาพ และหลังสแกนยังใช้ fallback เดิม
- เหตุการณ์ผูกกับ scan ID/แท็บ ป้องกันผลล่าช้าข้ามชุด; ตัวเลือกกรองหน้าว่างจำแยกแต่ละแท็บ
- รอบนี้ไม่เปลี่ยนระบบเลือก/ลบ ไม่ทำระบบประกอบภาพชิ้นส่วน และไม่บันทึกภาพไปโฟลเดอร์ปลายทางอัตโนมัติ

ทดสอบเพิ่ม: `npm run test:filters` และ `npm run test:filters:chrome`.
ผลเว็บจริงอ้างเฉพาะ URL และรูปแบบที่เปิดในรอบทดสอบ: MangaDex เป็นหน้าที่ตัวอ่านแสดง ไม่ใช่การยืนยันว่าเก็บทั้งตอน; BookWalker เป็นตัวอย่างสาธารณะ ไม่ใช่หนังสือฉบับเต็ม.

## 1.5.0 — Manga mode + Continuous Chapters

- เพิ่มสวิตช์ **เว็บทั่วไป / มังงะ-มังฮวา** แยกงานชัดเจน: เว็บทั่วไปใช้ตัวเก็บภาพเดิมและไม่เปิดระบบ Chapter; โหมดมังงะจึงค่อยแสดงตัวเลือก **ไล่ตอนถัดไปอัตโนมัติ**.
- Continuous mode สแกนและบันทึกตอนปัจจุบัน จากนั้นหา/เปิดตอนถัดไป สแกนใหม่ และทำซ้ำจนไม่มีตอนถัดไปหรือผู้ใช้กดหยุด.
- ตัวตรวจ Next Chapter ไม่ผูกโดเมน: ใช้ `rel=next`, ข้อความ/aria/title/class/id, SVG arrow, chapter selector, URL sibling, opaque chapter ID/UUID และ semantic button ที่ไม่มี href.
- รองรับปุ่ม JavaScript/placeholder เช่น `#/next/`: แอปกดคอนโทรลที่ยืนยันว่าเป็น Chapter Next แล้วรอ URL/title/heading เปลี่ยนจริงก่อนนับว่าผ่าน.
- ถ้าปุ่ม Next ไม่ทำงาน แต่หน้า reader มีลิงก์ **All chapters / รวมตอน** ระบบสามารถเปิดหน้ารวมตอนแล้วเลือกตอนที่สูงกว่าที่ใกล้ที่สุดเป็น fallback.
- เลขตอนใช้การเทียบเป็นส่วน ไม่ใช่ float: `1.1 → 1.2 → ... → 1.10` ถูกลำดับ และรองรับรูปแบบ `ตอนที่-6-3` เป็น 6.3; ไม่มีการเดา URL ด้วยการ +1 แบบตายตัว.
- ปุ่ม/ลิงก์ `Next Page`, Previous และ Next ที่ disabled ถูกตัดออก เพื่อไม่ให้หน้าภายในตอนเดียวกันหรือหน้าสุดท้ายถูกเข้าใจผิด.
- ในโหมดต่อเนื่อง ช่องชื่อชุดภาพเปลี่ยนเป็น **เลขโฟลเดอร์เริ่มต้น** เช่น `7`; แต่ละตอนใช้ `7`, `8`, `9`... ตรง ๆ และหยุดถ้าเลขนั้นมีอยู่แล้ว แทนการเติม `-2`.
- ใช้ตัวกรองและลำดับภาพชุดเดียวกับ UI ทุกตอน พร้อม guard สำหรับ URL วนซ้ำ, หน้า verification/access denied, ตอนที่บันทึกไม่ได้เลย และเพดาน 500 ตอนต่อการรัน.
